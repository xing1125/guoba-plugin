# 锅巴后台 B 端正规化改造蓝图

> 基线：后端 Guoba-Plugin（9 Service + 9 Controller）+ 前端 guoba-web-fork（12 页面）
> 目标：把「单管理员功能面板」升级为「正规多角色 B 端管理后台」
> 定稿：2026-10-18

---

## 一、改造四大支柱

| 支柱 | 现状 | 目标 |
|------|------|------|
| RBAC 权限体系 | 硬编码 `admin`、JWT 只塞 username | 多用户 + 角色 + 菜单/操作两级权限 |
| 审计与安全 | 仅少数模块落 audit_log | 全量操作审计 + 登录日志 + 敏感操作二次确认 + 防刷 |
| 数据能力 | 各页自行拉数据 | 通用搜索/筛选/排序 + CSV 导出 + 快照报表 |
| 体验与规范 | 各页样式不统一 | 统一列表规范 + 骨架屏/空态 + 通知中心 + 快捷键 |

---

## 二、分期与交付物（一次性连续推进，逐项自测验收）

### 阶段 1 —— RBAC 底座（数据层）
1. `DbService` 新增表：
   - `admin_user`（id, username, password_hash, nickname, role, status, created_at, last_login_at）
   - `admin_role`（role, name, menus JSON, ops JSON, builtin）—— 也可先内置三角色常量
   - `login_log`（id, username, ip, ua, success, reason, created_at）
2. 密码哈希：bcrypt（或 node 内置 `crypto.scrypt`，避免新增依赖）
3. 启动时种子：默认超管 `admin`（密码可配置/首登强制改密）+ 预设角色
   - `super` 超管 / `admin` 管理员 / `viewer` 只读
4. `AdminService` 新增用户/角色 CRUD

### 阶段 2 —— 鉴权升级
1. `LoginService.signToken` 的 JWT payload 加入 `uid` + `role`
2. `TokenInterceptor` 校验后注入 `req.user`（含角色 + 权限集合）
3. 新增权限校验：路由 → 操作码映射，中间件/注解拦截
4. 登录接口改造：账号密码登录（保留验证码通道向后兼容）
5. 登录成功/失败写 `login_log`，失败限流（Redis 计数）

### 阶段 3 —— 全量审计
1. `DbService.audit` 统一封装，所有 Controller 写操作强制落审计（actor 从 `req.user` 取）
2. 敏感操作（删账号、清数据、退群、改权限）加二次确认 + 审计高亮
3. 前端新增「审计日志」页（筛选 actor/action/时间 + 分页）

### 阶段 4 —— 数据能力
1. 通用列表组件封装（搜索框 + 排序 + 分页 + 密度切换）
2. CSV 导出（前端生成，复用列表数据，带表头/时间戳文件名）
3. 数据看板图表增强 + 定时快照（SyncService 已有，补导出入口）

### 阶段 5 —— 体验与规范
1. 统一列表页模板：`g-table-page` 骨架（工具栏 + 批量 + 空态 + 骨架屏）
2. 全局通知中心（顶部铃铛，聚合审计/异常告警）
3. 键盘快捷键（`?` 呼出帮助、`g`+`h` 回首页等）
4. 深浅主题细节统一

## 三、角色权限模型（预设）

| 角色 | 菜单可见 | 写操作 | 高危操作 |
|------|---------|--------|---------|
| super 超管 | 全部 | 全部 | 允许（含二次确认） |
| admin 管理员 | 除「系统/权限」外全部 | 大部分 | 部分需超管 |
| viewer 只读 | 全部（只读态） | 无 | 无 |

> 菜单/操作权限建议后端下发 `menus` + `ops` 两套，前端据此渲染与禁用。

---

## 四、风险与兼容

- **向后兼容**：保留 `#锅巴登录` 验证码通道与快速登录链接，默认映射到已有 admin 角色，避免影响现网。
- **不碰业务数据**：只新增后台管理自身的数据表（admin.db），不动 `app/data/db.db` 主库。
- **每次改动**：改 Controller/Service 后需重启 Bot 生效（锅巴启动时加载）。
- **前端构建**：~2.5min，改完构建 → 截图验收 → 部署 → CHANGELOG → commit/push。
